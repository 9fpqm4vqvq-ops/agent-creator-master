## New behavioral coverage

The 59 new v0.4 scenarios cover real local SQLite persistence, read transactions,
HTTP data/count consistency and refusal of writes/unsafe Hosts/paths, browser-safe
text rendering, distinct actual/estimated/unknown accounting, inclusive-cache cost
arithmetic, cumulative replay/revision conflicts, all five budget scopes, thresholds,
capped unknown-cost authorization, expiry/config binding, reservation reconciliation,
one execution per handoff, explicit idempotent intake and research-cache reuse.

Health checks cover missing profiles/runtimes/skills, drift, restart with missing
skills, partial upstream verification and separate QA links. Knowledge checks cover
category metadata/TTLs, stale/conflicting claims, ACLs, immutable history, deduplicated
research requests, exact QA hashes/dates, old-source rejection, edit invalidation,
supersession, historical retrieval and provider/category compatibility.

Maintenance checks cover disabled defaults, actual deterministic ticks/history,
AI request queuing without model invocation, cross-connection overlap protection,
lease recovery, failure backoff/redaction/exhaustion, fixed principals/handlers and
calendar due dates. Change checks cover isolated staging, unsafe paths/symlinks,
tampering, separate QA, actual scoped authorization, idle-task enforcement, permission
expansions, byte/registry/Vault backups, partial write rollback, preserved skill usage,
change memory, later human edits and interruption/recovery gates.

Migration checks include a synthetic SQLite dump generated by the released v0.3
code (tests/fixtures/v03-snapshot.sql), missing-new-column assertions, stable task/
knowledge IDs and history, conservative holds, memory-only backup and existing
v0.2 upgrade/transaction rollback/future-version rejection scenarios.

## What these checks do not establish

QA invocation references, tool-failure references, provider usage/costs and business
findings in unit tests are **explicit fixtures**. Subprocess tests execute a fixed
fixture validation runner in an isolated copy; final combined validation executes
the real project suites. Neither is evidence of independently invoked model QA.
The browser used synthetic local tasks, not private operations or live services.

No authenticated Claude mission, live provider telemetry, billing hard cap, live
Skill Finder registry, current official source research, Notion connection, Obsidian
application, YouTube account, live broker, unattended OS service or profitability
was verified. Those remain separate operational acceptance tests/configuration.
The released ZIP must additionally pass extraction, manifest and regression checks
before its GitHub branch is updated. RELEASE-MANIFEST.json records portable bytes;
releases/SHA256SUMS.txt identifies the downloadable ZIP externally.
